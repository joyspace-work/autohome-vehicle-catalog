# 同事内部使用版

2026-10-26 整理现有汽车之家 Base，不重新采集源站，不改变参数值。

日常从“新能源车系”的“车系总览”找车，打开“配置版本”，在“配置索引”的“配置查询”选择具体款型，再打开“基本参数”等分类关联。颜色、特色配置和选装包保留一配置多条明细。来源页面和来源时间随当前记录保留。表中的参数来自既有采集快照；标配、选配、无、未披露及价格条件沿用既有数据。

每张业务表保留原视图作为中文业务入口，并增加“后台｜完整字段”。ID、哈希、JSON及原文备份在业务视图隐藏，后台视图完整展示。分类参数相对顺序沿用整理前已验收视图；不恢复独立长度、宽度、高度字段。

车系的“图片与来源”查看单张 `brochure_cover`、已有图库数量、动力/年款、来源和状态。多图URL JSON和图库分组JSON保留在后台视图；封面不证明具体配置、年款或颜色。

“图库状态”按现有数据判定：

- 已采：既有快照保存图库URL及动力/年款分组，每组限量采集，不表示官网全量。
- 部分：包含只用车系封面兜底或缺图的分组。
- 待采：现有快照没有图片URL，不等同于官网无图。
- 失败：现有说明明确记录采集失败。
- 来源暂停：现有说明记录401/403/429、验证码等限制，本次不重试。
- 待核验：JSON、计数或分组证据不一致。

上述状态不代表本次已检查所有URL的HTTP有效性。“图库状态说明”写明判定边界。现有图片、原始说明、来源时间和JSON不被状态计算覆盖。

`internal_release.py`只生成展示计划和证据状态，不请求源站，也不执行写表。现场备份、预览、小样回读、受限写入及完整验收脚本放在独立数据目录 `internal-release-20261026/`，不提交业务数据、附件token或登录信息。执行仅针对显式授权的实验Base、shengxu用户身份；公司原表保持只读。
